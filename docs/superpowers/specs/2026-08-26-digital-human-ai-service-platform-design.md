# 数字人服务管理平台领域重构与 AI 能力设计

日期：2026-08-26

状态：已确认，等待书面规格复核

范围：当前 `ZhiLianServicePlatform` 仓库

## 1. 背景与目标

当前系统最初作为小智服务的扩展服务，已经包含设备添加代理、问答表、数字人项目配置、图片上传，以及按项目配置 OpenAI/Dify 的大语言模型代理。系统将升级为独立的“数字人服务管理平台”，小智能力只是其中一个业务模块。

本次重构的目标是：

- 将现有“数字人项目”完整重构为“小智中间件服务”。
- 将大语言模型从小智服务记录中分离，形成可复用的模型配置。
- 建立独立的语音识别模型和图像生成模型管理。
- 建立面向数字人前端的“前端 AI 服务”，前端通过服务调用能力，不直接接触底层模型和供应器密钥。
- 使用 MySQL 持久化所有配置和任务，使用 MinIO 保存图片与异步任务文件。
- 在 API/Worker 重启后恢复未完成任务，满足长期维护、快速和稳定的要求。

## 2. 已确认的范围

### 2.1 首期供应器

| 能力 | 首期供应器 | 说明 |
|---|---|---|
| 大语言模型 | OpenAI、Dify | 由小智中间件服务绑定，并与问答表共同工作 |
| 语音识别 | 百度、火山 | 前端上传完整音频，平台异步识别 |
| 图像生成 | 火山方舟 Seedream | 同一模型配置支持文生图和单图图生图 |

图像生成不支持多图融合。Unity 参考项目当前通过同一个 Seedream 模型、同一个 `/api/v3/images/generations` 接口工作：不传 `image` 为文生图，传一张 Base64 图片为图生图。

Unity 参考项目当前的语音识别供应器实际为百度，不包含火山 ASR。平台复用其 `16kHz、16bit、单声道 PCM` 音频处理约定；火山调用参考小智的新版豆包大模型 ASR v3 非流式实现。

### 2.2 不在首期范围

- 多图融合生成。
- 流式语音识别。
- 语音合成、图像识别、图生视频等后续能力。
- Redis、Celery 或独立微服务拆分。
- 兼容旧的 `/projects` 管理接口；尚无外部前端接入旧接口。
- 修改 Unity 参考项目。

## 3. 总体架构

采用模块化单体。API、后台页面和 Worker 使用同一代码仓库与同一镜像，但以不同进程角色运行。

```text
管理员
  └─ 数字人服务管理平台
       ├─ 小智中间件服务
       ├─ 前端 AI 服务
       ├─ AI 能力管理
       │    ├─ 大语言模型
       │    ├─ 语音识别模型
       │    └─ 图像生成模型
       ├─ 问答表管理
       └─ 账号设置

小智平台
  └─ OpenAI 兼容代理
       └─ 小智中间件服务 → 问答表优先 → 大语言模型兜底

数字人前端
  └─ serviceCode + 服务 API Key
       └─ 前端 AI 服务
            ├─ 语音识别绑定 → 百度或火山
            └─ 图像生成绑定 → 火山 Seedream

API → MySQL 持久任务 → Worker → 外部供应器
                               └─ MinIO 临时输入/七天结果
```

模块之间通过明确的服务接口协作：路由只处理 HTTP 边界；领域服务负责校验、绑定与状态规则；供应器适配器只负责第三方协议；存储组件只负责 MySQL/MinIO；Worker 只负责领取和执行任务。

## 5. 小智中间件服务

### 5.1 职责

小智中间件服务保留现有数字人和设备相关配置：

- 服务编码和前端显示名称。
- 标题、副标题、推荐问题。
- 背景、唤醒、菜单栏、键盘、语音、首页、长按说话、点击发送等图片。
- 语音唤醒开关、唤醒词、监听文字、唤醒需求数量。
- 设备名称和整数型 `agentId`。
- 发布/停止发布。

模型和问答关系调整为：

- 一个小智中间件服务绑定一个大语言模型。
- 一个小智中间件服务绑定一个问答表。
- 不绑定语音识别模型或图像生成模型。
- 不同小智中间件服务可以复用同一个大语言模型或问答表。

### 5.2 请求规则

小智继续使用 OpenAI 兼容的 `POST /v1/chat/completions`。请求中的模型标识解析为小智中间件服务编码：

1. 校验代理 API Key 和服务发布状态。
2. 对用户问题执行忽略首尾空格和大小写的规范化精确匹配。
3. 命中问答表时直接返回固定答案。
4. 未命中时调用服务绑定的大语言模型。
5. 上游失败时返回配置的稳定兜底文本。

绑定的大语言模型或问答表不可用时，禁止发布该服务。已发布服务的绑定模型被停用后，新请求返回明确的服务不可用错误，不静默切换其他模型。

## 6. 模型管理

### 6.1 统一交互形式

三类模型的管理页面模仿小智平台。列表显示模型名称、模型编码、供应器、排序号、启用状态和更新时间。新增/编辑弹窗分为：

1. 模型信息：模型名称、模型编码、供应器、排序号、文档地址、备注、是否启用。
2. 调用信息：根据供应器动态显示字段。

敏感字段只显示掩码；编辑时留空表示保持原值。页面提供“测试连接”按钮，返回中文结果。被服务绑定的模型不可归档；停用前显示受影响服务。

### 6.2 大语言模型

OpenAI 调用信息：

- 基础 URL。
- 模型名称。
- API Key。
- 请求超时。

Dify 调用信息：

- 基础 URL。
- 应用模式。
- API Key。
- 请求超时。

### 6.3 语音识别模型

百度调用信息：

- AppID。
- API Key。
- Secret Key。
- 语言参数，默认 `1537`。

火山调用信息：

- AppID。
- Access Token。
- 资源 ID。
- 语言。
- 可选热词表和纠错表参数。

火山首期使用豆包大模型 ASR v3 非流式协议。平台接收完整文件，统一转码后由 Worker 通过供应器协议提交，不向前端暴露 WebSocket 或供应器认证细节。

### 6.4 图像生成模型

火山 Seedream 调用信息：

- API 地址，默认火山方舟图片生成接口。
- API Key。
- 实际模型 ID。
- 默认宽度和高度。
- 请求超时。
- 是否添加水印。

同一配置支持两种调用：

- 没有参考图：文生图。
- 一张参考图：单图图生图。

平台遵守供应器最小像素要求。目标尺寸低于接口限制时，按原始宽高比放大请求尺寸，生成后再缩放为前端请求的目标尺寸。

## 7. 前端 AI 服务

### 7.1 服务配置

每条前端 AI 服务包含：

- 服务名称。
- 唯一服务编码 `serviceCode`。
- 是否启用。
- 备注。
- 独立服务 API Key。
- 每分钟任务上限。
- 最大并发任务数。
- 可选允许访问域名列表。
- 一个可选语音识别模型绑定。
- 一个可选图像生成模型绑定。

未绑定的能力不可调用。以后增加语音合成等能力时，增加新的能力模型表、适配器和类型化绑定表，不向现有表塞入万能 JSON。

### 7.2 API Key

服务 API Key 只在创建或重新生成时展示一次。数据库仅保存安全哈希、标识前缀和末尾字符，不保存可还原明文。重新生成后旧 Key 立即失效。

浏览器中的 API Key 无法成为绝对秘密，因此平台同时提供服务级限流、并发限制和可选 Origin 校验。Unity 等不发送 Origin 的原生客户端仅使用 API Key 和限流控制。

### 7.3 后台页面

前端 AI 服务编辑页分为：

1. 基本信息。
2. 能力绑定。
3. 接口安全。
4. 最近调用。

最近调用显示任务类型、状态、耗时、模型、供应器、创建/完成时间和安全错误摘要，不提供已删除的原始输入文件，不展示供应器密钥。

停用服务后禁止创建新任务，但仍允许使用当前有效 API Key 查询该服务此前任务的状态和结果。

## 8. 公开 API

所有接口的 Swagger 标题、字段、示例、状态和错误说明使用中文。

### 8.1 查询服务能力

```http
GET /api/v1/ai-services/{serviceCode}
Authorization: Bearer <服务API Key>
```

返回服务名称、启用状态、可用能力和接口版本，不返回底层模型、供应器配置或任何供应器密钥。

### 8.2 创建语音识别任务

```http
POST /api/v1/ai-services/{serviceCode}/speech-tasks
Authorization: Bearer <服务API Key>
Content-Type: multipart/form-data
Idempotency-Key: <可选，推荐>
```

音频支持 `wav`、`mp3`、`m4a`、`ogg`、`webm`。平台校验内容而不是只信任扩展名，然后统一转为 `16kHz、16bit、单声道 PCM`。

### 8.3 创建图像生成任务

```http
POST /api/v1/ai-services/{serviceCode}/image-tasks
Authorization: Bearer <服务API Key>
Content-Type: multipart/form-data
Idempotency-Key: <可选，推荐>
```

字段：

- `prompt`：必填。
- `image`：可选，支持 `jpg`、`jpeg`、`png`、`webp`；最多一张。
- `width`、`height`：可选，缺省使用模型默认值。

### 8.4 查询任务

```http
GET /api/v1/ai-services/{serviceCode}/tasks/{taskId}
Authorization: Bearer <服务API Key>
```

状态机：

```text
pending → processing → succeeded
                     ↘ failed
succeeded → expired
```

语音成功结果：

```json
{
  "taskId": "任务ID",
  "taskType": "speech_recognition",
  "status": "succeeded",
  "result": { "text": "识别后的文字" }
}
```

图像成功结果：

```json
{
  "taskId": "任务ID",
  "taskType": "image_generation",
  "status": "succeeded",
  "result": {
    "imageUrl": "平台临时下载地址",
    "expiresAt": "过期时间"
  }
}
```

### 8.5 图像下载

MinIO 的 `minio:9000` 是 Docker 内部别名，不能返回给前端。`imageUrl` 指向平台自己的短期签名下载接口。平台验证签名、任务状态和过期时间后从 MinIO 流式读取对象。短期链接过期后，前端重新查询任务即可获得新链接；对象总保留期仍为七天。

### 8.6 幂等和错误

同一服务、任务类型和 `Idempotency-Key` 只创建一个任务；重复提交返回原任务。错误响应包含稳定错误码、中文说明和追踪 ID，不返回第三方完整错误体、文件内容或密钥。

主要错误类别包括：服务不存在、服务停用、API Key 无效、能力未绑定、模型停用、文件格式错误、文件超限、参数错误、并发/频率超限、供应器暂时不可用、任务不存在和结果已过期。

## 9. 异步任务与 Worker

### 9.1 为什么使用 MySQL 队列

本阶段选择 MySQL 持久任务队列，不使用 API 进程内后台任务，也不引入 Redis/Celery。这样任务在 API/Worker 重启时不会丢失，同时避免新增运维组件。当前任务量下，带索引的短轮询满足性能要求；未来吞吐显著增长时，可以在保持任务领域接口不变的前提下替换调度实现。

### 9.2 领取和恢复

Worker 使用数据库行锁与租约领取任务：

- 通过 `SELECT ... FOR UPDATE SKIP LOCKED` 领取到期的 `pending` 任务。
- 写入 Worker 标识、租约到期时间、尝试次数和开始时间。
- 处理期间续租；完成时原子写入结果和终态。
- Worker 异常退出后，租约过期的 `processing` 任务重新进入可领取状态。
- 网络类临时故障按有限次数和退避时间重试。
- 鉴权、参数、格式等确定性错误直接失败。
- 超过最大尝试次数后进入 `failed`，不无限重试和重复扣费。

任务记录保留模型 ID、模型名称/供应器安全快照、耗时、错误码、错误摘要和追踪 ID。不得保存供应器密钥快照。

### 9.3 文件生命周期

- 音频和参考图先写入 MinIO 私有临时前缀，避免本地容器重启导致任务输入丢失。
- 任务成功或失败后删除输入文件。
- 异常遗留输入由清理器按安全过期时间删除。
- 生成结果写入 MinIO 私有结果前缀，保留七天。
- 七天后删除对象并将任务标记为 `expired`。
- 清理操作必须幂等；对象已不存在时仍可安全完成状态更新。

继续使用现有 `extended_` 表前缀，减少不必要的迁移风险；业务名和代码类型完整重构。

- `DigitalHumanProject`、`ProjectAsset` 及 `/projects` 路由、DTO、服务和页面全部重命名，不保留旧接口兼容层。

### 10.2 模型表

建立独立的通用信息表：

- `extended_llm_models`。
- `extended_speech_recognition_models`。
- `extended_image_generation_models`。

建立供应器专属的一对一配置表：

- `extended_llm_openai_configs`。

- `extended_asr_baidu_configs`。
- `extended_asr_volcengine_configs`。

供应器配置使用明确列，不使用万能 JSON。密钥列保存带版本的密文。模型编码在所属能力类别内唯一。

模型采用归档语义保留历史。正在被服务绑定的模型不能归档；解绑后可以归档，但历史任务仍可引用其标识和安全快照。

### 10.3 服务与绑定表

- `extended_frontend_ai_services`：服务基本信息、API Key 哈希、限流和启用状态。
- `extended_frontend_ai_service_speech_bindings`：一条服务最多一个语音识别模型。
- `extended_frontend_ai_service_image_bindings`：一条服务最多一个图像生成模型。
- 小智中间件服务增加 `llm_model_id`，保留 `qa_table_id`。

每类绑定使用真实外键和唯一约束。增加新能力时增加该能力自己的模型表和绑定表。

### 10.4 任务表

`extended_ai_tasks` 至少保存：

- 任务 ID、服务 ID、任务类型和状态。
- 语音模型 ID或图像模型 ID。
- 幂等键。
- 输入对象键、提示词和尺寸参数。
- 结果文字或结果对象键、结果过期时间。
- 尝试次数、下次尝试时间。
- Worker 标识、租约到期时间。
- 错误码、安全错误摘要和追踪 ID。
- 创建、开始、完成和更新时间。

数据库约束保证任务类型与模型外键、结果字段相互匹配。列表和领取路径建立组合索引。

## 11. 密钥与安全

- 外部供应器密钥使用独立的 `MODEL_CREDENTIAL_ENCRYPTION_KEY` 加密，不与管理员会话密钥复用。
- 密文带版本，支持未来轮换主密钥。
- 当前项目级 OpenAI/Dify 密文迁移时先使用现有机制解密，再用新主密钥重新加密。
- 服务 API Key 只保存密码学安全哈希，不能解密。
- 日志过滤 Authorization、API Key、Access Token、Secret Key、音频内容、图片 Base64 和供应器完整错误体。
- 测试连接接口使用当前管理员权限，做超时和并发限制，不把密钥返回页面。
- Unity 项目 Inspector 或源码中的供应器密钥不复制到平台代码；迁移到平台后应在供应器控制台轮换原密钥。

## 12. 数据库和 MinIO 部署

### 12.1 独立数据库

正式环境不再使用小智 MySQL 别名。平台连接 `Loan` 项目使用的共享正式 MySQL 实例，但创建自己的独立数据库，例如 `digital_human_service_platform`；不得把平台表写入 Loan 的 `opc_loan_db`。

连接信息全部来自环境变量：

- Production：共享正式 MySQL 主机和 `digital_human_service_platform` 数据库。
- Development：开发 MySQL 主机上的独立开发数据库 `digital_human_service_platform`（与正式环境使用不同主机或实例隔离）。
- 用户名和密码不写入仓库、设计文档或镜像。

### 12.2 正式数据库初始化

当前系统尚未在正式环境发布，因此不从小智数据库搬迁任何数据。首次上线流程为：

1. 在共享正式 MySQL 创建平台专用空数据库和专用数据库用户。
2. 通过环境变量配置平台专用数据库连接。
3. 在空数据库执行 Alembic，从 `0001` 初始化到最新版本。
4. 创建首个管理员并检查初始数据。
5. 启动 API/Worker，完成健康检查和冒烟验证后开放入口。

首次部署不读取、导出或修改旧小智数据库，也不向 Loan 的 `opc_loan_db` 写入任何表。Development 同样可以初始化独立空数据库；现有本地开发数据不属于正式上线数据。以后已经进入平台专用数据库的数据必须通过正常 Alembic 版本升级保留。

### 12.3 MinIO

正式容器通过共享网络的 `minio:9000` 别名访问 MinIO。使用平台独立私有 Bucket，例如 `digital-human-service-platform`，不复用 Loan 公开 Bucket。

Development 使用环境变量指定开发 MinIO 地址和独立 Bucket。内部 MinIO 地址不出现在公开 DTO；图片下载统一经过平台签名下载接口。

## 13. Docker Compose

同一镜像运行三个角色：

```text
digital-human-migrate  # Alembic 迁移，成功后退出
digital-human-api      # FastAPI、后台静态资源和公开 API
digital-human-worker   # MySQL 任务 Worker 和过期清理
```

`api` 和 `worker` 只有在 `migrate` 成功后启动。三者读取同一份环境配置并加入可访问共享 MinIO 的 Docker 网络。只有 API 暴露 HTTP 端口；Worker 和迁移容器不暴露端口。

## 14. 数据库结构升级规则

本次新增 Alembic 迁移从当前 `0005` 继续。正式空数据库会依次执行 `0001` 至最新版，此时下列数据转换处理零行；已有 Development 数据库原地升级时才执行实际记录转换：

1. 创建独立模型表、供应器配置表、前端 AI 服务表、绑定表和任务表。
2. 为每条现有项目级 OpenAI/Dify 配置创建一条独立大语言模型记录。
3. 不自动去重现有模型配置，避免错误合并不同项目的密钥。
4. 将服务绑定到新模型记录。
5. 重命名数字人项目、项目图片、设备映射外键及相关索引/约束。
6. 删除已经完成迁移的项目级 LLM 字段。
7. 保留问答表、设备、图片对象键、发布状态和时间字段。
8. 在提交前执行数量与外键完整性断言；任一断言失败则回滚。

迁移的 downgrade 仅用于开发验证。正式环境在后续每次数据库升级前备份平台专用数据库；生产回退依赖已验证的备份和兼容版本，不执行破坏性反向迁移。

## 15. 错误处理和可观测性

- 管理接口和公开接口使用统一响应结构与中文错误信息。
- 每个请求和任务都拥有 `traceId`，API 日志、任务记录和 Worker 日志可串联。
- 第三方 HTTP 状态、供应器错误码可以保存为受控诊断字段，但不得将完整响应直接返回前端。
- 健康检查区分 API 存活、MySQL 可用、MinIO 可用和 Worker 最近心跳。
- 概览页展示失败任务数、处理中任务数和供应器连接异常摘要，不展示敏感配置。

## 16. 验证方案

### 16.1 自动测试

- 模型 DTO 和供应器动态字段校验。
- 模型密钥加解密、掩码和轮换。
- 服务 API Key 生成、哈希验证和失效。
- 音频格式识别与统一转码。
- JPG/JPEG/PNG/WebP 内容校验与规范化。
- 百度 ASR、火山 ASR、火山 Seedream、OpenAI、Dify 适配器模拟测试。
- 固定问答优先与 LLM 兜底。
- 服务限流、并发限制和幂等提交。
- 任务状态机、行锁领取、租约续期、重试和重启恢复。
- MinIO 输入清理、七天结果过期和平台签名下载。
- 从当前 `0005` 数据库结构升级并验证数据完整。
- 管理员页面路由、表单动态字段、API Key 单次展示和中文错误。
- Swagger 中文标题、字段、示例和错误说明。

### 16.2 集成与恢复测试

- MySQL、MinIO、API、Worker 完整语音和图像任务链。
- Worker 处理过程中被停止，租约到期后由新 Worker 重新领取。
- API 重启期间任务继续处理，恢复后可查询结果。
- 重复 `Idempotency-Key` 不重复创建付费任务。
- MinIO 暂时不可用时任务有限重试，恢复后可继续。
- 全新平台专用数据库从 `0001` 初始化到最新版本。

真实供应器连通测试仅由管理员手动触发，不进入默认自动化测试，避免产生费用。

## 17. 完成标准

满足以下条件才视为完成：

- 后台名称、菜单、代码、数据库和 API 中不再将小智服务称为“数字人项目”。
- LLM 配置已独立并可被多个小智中间件服务复用。
- ASR 可配置百度和火山；图像生成可配置火山 Seedream。
- 前端 AI 服务可绑定 ASR/图像模型并拥有独立 API Key。
- 语音与图像均通过统一异步任务模式工作。
- 文生图和单图图生图可用，多图被明确拒绝。
- 任务在容器重启后可恢复，输入和七天结果按规则清理。
- 正式数据位于共享 MySQL 的平台专用数据库，不依赖小智 MySQL 别名，也不污染 Loan 业务库。
- 正式 MinIO 通过共享别名访问，前端只看到平台下载 URL。
- 正式平台专用空数据库可完整初始化，且不读取或污染小智、Loan 的业务数据库。
- 新增 Swagger、后台页面和错误提示全部中文化。
