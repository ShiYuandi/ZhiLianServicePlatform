# Swagger 全中文化设计

## 目标

让前端和后端维护人员无需阅读实现代码，即可在 `/docs` 中理解并调试全部接口。中文化覆盖系统状态、前端公开接口、管理员认证、后台概览、问答管理和设备映射六个分组，不改变现有接口地址、JSON 字段名、认证机制或业务行为。

## 文档结构

FastAPI 应用通过 `openapi_tags` 定义六个中文分组及分组说明，并补充中文应用简介。路由装饰器使用中文 `summary` 作为 Swagger 接口标题；接口函数使用中文 docstring 作为详细说明。FastAPI 自动读取 docstring，因此详细说明只有一个维护来源，代码阅读体验与 Swagger 保持同步。

所有路径参数、查询参数和上传文件参数都使用 FastAPI 参数元数据声明中文含义、取值限制及默认行为。所有请求和响应模型通过 Pydantic `Field` 声明中文字段说明，并为前端常用请求提供合法示例。

## 接口分组

| 分组 | 覆盖内容 |
| --- | --- |
| 系统状态 | 服务及数据库健康检查 |
| 前端公开接口 | 设备添加代理、按表名下载问答 Excel |
| 管理员认证 | 登录、退出、获取当前管理员、修改密码 |
| 后台概览 | 问答表、问答项和设备映射数量 |
| 问答管理 | 问答表和问答项 CRUD、批量添加、Excel 导入导出 |
| 设备映射 | 设备名称与小智 `agentId` 映射 CRUD |

分组名称与接口标题全部使用中文；为了不影响 OpenAPI 客户端生成和已有前端，路径、请求字段和响应字段保留当前名称。

## 认证与错误说明

后台接口的详细说明明确标注登录 Cookie 要求。所有会修改数据的后台接口进一步标注 `X-CSRF-Token` 要求及其来源。登录接口说明会写明成功后由服务写入 HttpOnly 会话 Cookie，并在响应中返回 CSRF Token。

Swagger 为常见响应状态提供中文解释，包括参数校验失败、未登录、CSRF 校验失败、资源不存在、数据冲突、文件格式错误、文件过大、上游小智平台异常和数据库不可用。错误响应继续使用现有统一结构：`code`、`message`、`requestId`。

Excel 下载和导出接口明确声明响应为 `.xlsx` 二进制文件；Excel 导入接口说明两列表头、`append` 与 `replace` 模式以及文件限制。

## 代码维护规则

- `summary` 只写简短中文动作名称。
- docstring 负责接口用途、认证要求和行为细节，并作为 Swagger 详细说明。
- `Field`、`Path`、`Query` 和 `File` 负责参数级中文说明。
- 示例必须符合当前校验规则，不包含真实密码、Token、JSESSIONID 或其他秘密。
- 新增接口时必须归入六个现有分组之一；只有出现独立业务领域时才增加新分组。

## 验证方案

增加 OpenAPI 自动化测试，直接检查 `/openapi.json`：

1. 六个分组名称及说明均为中文。
2. 所有纳入 Swagger 的接口都有中文 `summary` 和非空中文 `description`。
3. 公开设备添加、Excel 下载以及全部后台接口的关键参数具有中文说明。
4. 请求模型字段具有中文说明，前端常用模型包含合法示例。
5. 接口路径和现有字段名未发生变化。

最后运行完整后端测试、Ruff 检查和格式检查，并在浏览器中打开 `/docs` 抽查分组、参数说明、示例和 Excel 响应展示。
