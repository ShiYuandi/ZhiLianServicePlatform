# 小智固定问答与外部大模型代理设计

日期：2026-08-25

## 1. 目标与范围

在现有小智数字人中间件中新增 OpenAI 兼容的大语言模型代理。小智将本服务配置为 OpenAI 类型的大模型，并通过项目编码选择数字人项目。中间件先在项目绑定的问答表中精确查找固定答案；命中时直接返回固定答案，未命中时调用全局配置的 OpenAI 兼容外部模型并返回结果。

本模块负责文本回答，不负责语音合成。小智继续使用其现有 TTS 流程把回答转换为语音并发送给数字人前端。本次不修改小智服务源码，不引入 Dify 工作流，不实现模糊匹配、语义向量检索、对话记录持久化或外部模型后台配置页面。

## 2. 接入方案

中间件新增：

```http
POST /v1/chat/completions
Authorization: Bearer <LLM_PROXY_API_KEY>
```

小智使用现有 OpenAI Provider 接入：

```yaml
type: openai
base_url: http://zhilian-service-platform:8000/v1
api_key: ${LLM_PROXY_API_KEY}
model_name: museum-a
```

`model_name` 对应数字人项目的唯一 `projectCode`。请求中的 `model` 用于选择项目，不作为外部模型的真实模型名称。中间件调用上游时把它替换为环境变量 `UPSTREAM_LLM_MODEL`，对小智返回时仍使用项目编码。

选择此方案是因为它不侵入小智源码，复用小智当前流式 OpenAI 调用能力，问答表修改可立即生效，并且中间件可以独立测试、部署和升级。

## 3. 数据模型与关系

`extended_digital_human_projects` 新增：

- `qa_table_id`：可空外键，指向 `extended_qa_tables.id`。

关系规则：

- 一个数字人项目最多绑定一张问答表。
- 一张问答表可以被多个项目复用。
- 草稿项目允许暂时不绑定问答表。
- 发布项目时必须绑定一张仍然存在的问答表。
- 已发布项目必须先停止发布，才能更换问答表。
- 被任意项目绑定的问答表不能删除，删除接口返回冲突提示。
- 外键使用限制删除策略并为 `qa_table_id` 建立索引。

迁移只增加关联字段和约束，不修改现有项目发布状态，不修改现有问答内容。现有项目的 `qa_table_id` 初始为空，由管理员手动选择。

## 4. 后台管理

项目编辑器增加“绑定问答表”搜索下拉框，显示问答表名称与问答条数。项目列表增加“问答表”一列。后台项目 DTO 增加：

```ts
qaTableId: number | null
qaTableName: string | null
```

发布完整度和发布校验增加“问答表”。问答表删除被拒绝时，错误信息列出关联项目的前端显示名称，管理员需要先停止发布并解除绑定。

公开数字人项目 DTO 不增加问答表字段，普通数字人前端不需要知道内部知识表结构。原有 Excel 导入、导出与下载能力保留，但数字人前端不再依赖 Excel 执行匹配。

## 5. OpenAI 请求契约

第一版接受小智当前使用的 OpenAI Chat Completions 请求字段：

- `model`：必填，作为 `projectCode`。
- `messages`：必填，按顺序保留完整上下文。
- `stream`：支持 `true` 和 `false`。
- `max_tokens`
- `temperature`
- `top_p`
- `frequency_penalty`
- `tools`
- `tool_choice`

未知的兼容扩展字段不参与固定问答逻辑；支持安全透传的字段由上游客户端白名单明确维护，禁止把任意请求键无条件转发。

中间件从后向前选取最后一条 `role=user` 且 `content` 为字符串的消息作为当前问题。缺少用户消息、用户内容不是纯文本、消息数量或文本长度超过限制时返回 OpenAI 格式的 `400`。本模块不处理图片、音频或其他多模态消息。

## 6. 固定问答匹配

匹配只查询当前项目绑定的问答表，使用现有规范化规则：

- 去除问题前后空格。
- 使用 Unicode `casefold` 忽略大小写。
- 保留中间空格和标点，不做改写。
- 不做包含匹配、拼音匹配、编辑距离或语义相似匹配。

查询使用已有问题指纹缩小范围，并再次比较 `normalized_question`，避免只依赖哈希。命中后原样返回数据库中的 `answer`，不调用外部模型，也不让外部模型改写固定答案。

示例：表中问题为“开放时间是什么？”，输入“  开放时间是什么？  ”命中；输入“什么时候开放？”不命中并转外部模型。

## 7. 请求处理流程

1. 校验 Bearer 密钥。
2. 校验请求结构和输入长度。
3. 按 `model` 查找项目。
4. 只允许已发布项目；草稿或不存在的项目返回 404。
5. 校验设备映射存在且已启用；停用时返回 403。
6. 校验项目已绑定问答表；关系异常时返回 409。
7. 提取最后一条用户纯文本消息并执行精确匹配。
8. 命中时生成固定答案响应。
9. 未命中时把完整对话和受支持参数发送给全局外部模型。
10. 将上游内容增量和工具调用转换为本服务统一的 OpenAI 响应。

固定问答和外部模型共用同一响应构造层，避免两条路径产生不同协议。对外 `model` 始终为请求中的项目编码，不暴露上游真实模型名称、地址或供应商。

## 8. 流式与非流式响应

### 8.1 `stream=true`

响应媒体类型为 `text/event-stream`，采用 OpenAI Chat Completions SSE 格式：

- 首个数据块声明 `assistant` 角色。
- 后续数据块包含 `delta.content` 或 `delta.tool_calls`。
- 最后一个完成数据块带 `finish_reason`。
- 以 `data: [DONE]` 结束。

固定答案可以作为一个完整内容块返回，不改变答案文字。外部模型按其增量持续转发，小智可以立即进行后续分句和 TTS。

### 8.2 `stream=false`

返回标准 `chat.completion` JSON，`choices[0].message` 包含完整内容或工具调用。固定答案不伪造 Token 使用量；上游提供可靠 usage 时才返回规范化 usage。

## 9. 外部模型客户端

第一版只支持 OpenAI 兼容外部模型。配置按 development 和 production 隔离：

```env
LLM_PROXY_API_KEY=replace-with-a-random-service-key
UPSTREAM_LLM_BASE_URL=https://replace-with-provider/v1
UPSTREAM_LLM_API_KEY=replace-with-provider-key
UPSTREAM_LLM_MODEL=replace-with-model-name
UPSTREAM_LLM_TIMEOUT_SECONDS=60
UPSTREAM_LLM_FALLBACK_TEXT=抱歉，智能问答服务暂时不可用，请稍后再试。
```

客户端接收完整 `messages` 和受支持的生成、工具参数。`model` 始终使用 `UPSTREAM_LLM_MODEL`。接口通过抽象客户端隔离供应商实现，测试使用内存或 Mock Transport，不访问真实外部模型。

全局外部模型配置适用于所有项目。不同项目的角色、系统提示词和历史上下文继续由小智构造在 `messages` 中，因此不需要在中间件重复维护提示词。

## 10. 鉴权与输入限制

- 小智调用密钥与上游模型 API Key 完全分离。
- Bearer 密钥使用恒定时间比较。
- 未配置或密钥错误返回 OpenAI 格式 401。
- production 启动时校验代理密钥、上游地址、上游密钥、模型名和正数超时；示例占位值视为无效。
- Swagger 提供全中文接口、字段和响应说明，但不放入真实密钥或可用密钥示例。
- 配置最大消息数量、单条文本长度和请求总文本长度；超限返回 400。
- 不接受用户提供的上游 URL、上游 API Key 或真实上游模型名。

## 11. 错误处理

接口业务错误统一使用 OpenAI 错误结构：

```json
{
  "error": {
    "message": "中文错误信息",
    "type": "invalid_request_error",
    "code": "PROJECT_NOT_FOUND"
  }
}
```

状态规则：

- 401：代理 Bearer 密钥缺失或错误。
- 403：项目设备映射已停用。
- 404：项目不存在或未发布。
- 400：请求体、模型名、消息或输入长度不合法。
- 409：已发布项目关联数据异常。

外部模型连接失败、超时、限流或服务错误不直接暴露给小智：

- 在尚未输出任何内容时失败，按原请求的流式或非流式协议返回 `UPSTREAM_LLM_FALLBACK_TEXT`。
- 流式回答已经输出部分内容后中断，追加“抱歉，回答生成中断，请稍后再试。”，发送正常完成块和 `[DONE]`。
- 不自动重试，避免增加不可控等待时间或在流式输出后产生重复内容。

固定问答完全不依赖外部模型，外部服务故障时仍可正常回答。

## 12. 日志与隐私

不保存用户消息、对话历史、固定答案正文或外部模型回答。结构化日志只记录：

- 请求编号。
- 项目编码。
- 回答来源：`fixed`、`upstream` 或 `fallback`。
- 是否流式。
- 总耗时与首字耗时。
- 外部错误类别和状态码。

日志不得记录 Bearer 密钥、上游 API Key、完整请求头、请求正文或响应正文。

## 13. 兼容性与部署

正式环境中，中间件与小智服务位于同一 `shared_net`，小智通过 `http://zhilian-service-platform:8000/v1` 访问。接口路径、请求和响应兼容小智当前 `core.providers.llm.openai` Provider，无需修改小智源码。

本模块支持小智普通流式回答及带 `tools` 的函数调用路径。固定问答命中时直接返回文本，不触发工具；未命中时透传工具定义和工具选择，并保留外部模型返回的工具调用增量。

## 14. 测试与验收

自动化测试覆盖：

- 前后空格和大小写规范化命中。
- 近似问题不命中并调用上游。
- 多项目问答表隔离和问答表复用。
- 固定答案命中时上游零调用。
- 流式 SSE 数据块、完成原因和 `[DONE]`。
- 非流式标准 JSON。
- 完整上下文、生成参数、工具定义和工具调用转发。
- Bearer 鉴权、草稿项目、停用设备、非法消息和输入超限。
- 上游连接失败、超时、限流和流式中断兜底。
- 发布必须绑定问答表，已绑定问答表禁止删除。
- Alembic 从当前版本升级、降级、再次升级并保留历史数据。
- 中文 OpenAPI 路径、字段、参数和错误响应。

人工验收：

1. 后台给项目绑定问答表并发布。
2. 小智使用项目编码作为模型名连接中间件。
3. 表中问题返回固定答案并由小智 TTS 播放。
4. 表外问题返回外部模型答案并由小智 TTS 播放。
5. 将上游地址临时改为不可用地址，固定问答仍正常，表外问题播放兜底文本。
6. 检查日志只包含项目编码、来源、耗时和错误类型。

## 15. 不在本次范围

- 模糊匹配、向量数据库、Embedding 或 RAG。
- 多张问答表按优先级组合查询。
- 在后台维护上游模型密钥。
- 保存和查看用户对话记录。
- 模型用量计费、配额或按项目限流。
- 修改小智 TTS、意图识别、记忆或插件实现。
